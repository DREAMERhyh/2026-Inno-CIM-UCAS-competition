# Task2 总结 — SimpleCNN @ CIFAR-100：NAT（随机 α）训练的鲁棒性代价与收益

## 1. 实验设置

| 项目     | 内容                                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 训练范式 | NAT：训练时以随机 α ~ U(−0.3, +0.3) 注入非线性失真（alpha_mode=random）                                                            |
| 两种模式 | scratch（随机初始化，120 epochs）/ finetune（从 clean 基线权重 `checkpoints_cifar100/simple_cnn/best_model.pth` 起步，120 epochs） |
| 对照基线 | task1 的 clean SimpleCNN：clean acc **59.99%**，α 扫描见 task1 总结                                                                |
| 评估协议 | 与 task1 完全一致：全量测试集、α 网格 {−0.3,…,+0.3}、best 权重复评                                                                 |
| 产物目录 | `outputs_cifar100/task2_nat_simplecnn/`（scratch 与 finetune 分目录）                                                              |

**数据配对核查（重要）**：初收到材料中两组 CSV 与 metrics 交叉错位——CSV 的 α=0 复评值必须等于该次训练的 best_test_acc，实际出现完美交叉（60.16↔finetune best、60.70↔scratch best）。本文档按修正后配对书写（60.70 → scratch；60.16 → finetune），已通过目录核查确认。头条结论与配对无关。

**一致性核对**：scratch CSV α=0 = 60.70 = best_test_acc ✓；finetune CSV α=0 = 60.16 = best_test_acc ✓。

## 2. 训练动态与干净精度

| 指标                      | clean 基线 | NAT-scratch | NAT-finetune |
| ------------------------- | ---------- | ----------- | ------------ |
| best_test_acc (%)         | 59.99      | **60.70**   | 60.16        |
| best_epoch                | 114/120    | 107/120     | **57/120**   |
| final train/test gap (pp) | 13.8       | 12.0        | 14.3         |
| clean loss                | 1.496      | 1.477       | 1.465        |

1. **clean 精度不降反微升**（+0.71 / +0.17 pp）：随机失真注入起到了轻度正则化作用，**没有出现文献中常见的 clean–robustness 权衡的 clean 侧损失**。
2. **scratch 全面略优且更便宜**：clean 更高（+0.54pp）、总计算量减半（120 vs 隐含 240 epochs）；finetune 唯一效率优势是更早达峰（57 vs 107），但若把基线训练计入，其总开销是 scratch 的两倍。
3. finetune 达峰后轻微回落（best 60.16 → final 59.89），scratch 在 107/120 仍在改善——**scratch + 更长 schedule 是一条值得记录的低成本改进路径**。

## 3. 鲁棒性扫描：核心发现是"方向再分配"

| α    | 基线  | NAT-scratch | Δ         | NAT-finetune | Δ     |
| ---- | ----- | ----------- | --------- | ------------ | ----- |
| −0.3 | 42.91 | 46.20       | **+3.29** | 45.79        | +2.88 |
| −0.2 | 51.14 | 52.68       | +1.54     | 53.07        | +1.93 |
| −0.1 | 57.22 | 58.14       | +0.92     | 58.22        | +1.00 |
| 0.0  | 59.99 | 60.70       | +0.71     | 60.16        | +0.17 |
| +0.1 | 58.09 | 57.21       | −0.88     | 56.82        | −1.27 |
| +0.2 | 47.62 | 42.94       | **−4.68** | 44.06        | −3.56 |
| +0.3 | 28.09 | 21.41       | **−6.68** | 24.81        | −3.28 |

**关键发现**：

1. **【头条】NAT 在 α 轴上执行了一次"鲁棒性再分配"**：两种模式的 Δ 值随 α 近似严格单调递减（scratch：+3.29 → −6.68，七个测点严格单调）——负 α（幅值放大）侧全面小幅受益（+0.9~+3.3pp），正 α（幅值压缩）侧全面受损（−0.9~−6.7pp），零交叉点都在 α≈+0.05 附近。
2. **NAT 加剧了主要短板**：task1 已确认 +α（压缩）是更脆弱的方向；对称随机 α 训练**没有补强它，反而进一步恶化**（+0.3 相对跌幅 53.2% → 64.7% (scratch) / 58.7% (finetune)）。这是本研究目前最重要的**反直觉负结果**。
3. **方向不对称性扩大**：|α|=0.3 的正负精度差从基线的 14.8pp 扩大到 24.8pp（scratch）/ 21.0pp（finetune）（此结论与配对无关，两种配对下均成立）——**对称的训练扰动分布，产出更不对称的鲁棒性轮廓**。
4. 负向相对跌幅两模式完全一致（均 23.9%，基线 28.5%）：NAT 对放大方向的改善幅度有限且封顶。
5. loss 与精度轮廓一致；一处细节：scratch 在 +0.3 精度更低但 loss 也更低（3.08 vs 3.28）——其错误预测置信度更低，提示两模式在压缩崩溃区的错误形态不同（校准差异，记录备查）。

## 4. scratch vs finetune

1. **总体是平手**：全部 7 个测点差异 ≤3.4pp，多数 <1pp，与单种子随机性同量级——**差异方向需多种子才能定论**（当前证据不足以写强结论）。
2. 修正配对下的差异轮廓：finetune 在压缩尾部保留更多鲁棒性（+0.3：+3.40pp；+0.2：+1.12pp），scratch 在 clean（+0.54pp）与 −0.3（+0.41pp）略优。若定性描述：**预训练起点的模型对"本就脆弱的方向"保留得稍好，从零训练的模型把 clean 推得稍高**。
3. 综合计算成本（finetune 隐含双倍 epochs），**scratch 是当前更优的默认选择**；finetune 的价值限于压缩尾部那 ~3pp，且未经统计显著性确认。

## 5. 机制候选解释（均为假设，待检验）

- **H1（工程性解释，最先排除）训练–评估注入失配**：需核对 task2_nat.py 训练时扰动的注入协议（层范围是否与 task1 全层同注一致、α 每 batch/每 epoch 采样方式、是否含幅值缩放以外的成分）。若训练时从未见过"全层同时 +0.3"，尾部恶化就有了直接解释。**行动项：读 task2_nat.py 的扰动注入代码段**。
- **H2（优化层面）"弃尾"效应**：均匀采样下，降低平均失真损失的最省力路径是守住高密度的小 |α| 区域与较易的 −α 侧，放弃本就最难修复的 +α 尾部——与 Δ 单调递减的观测形态吻合。
- **H3（表征几何）幅值偏移假说**：若 NAT 使 clean 表征的激活幅值整体收缩（正则化效应），则 −α 放大将"复原"到良好工作区、+α 压缩则"雪上加霜"。**可检验预测**：对 NAT checkpoint 跑 task1 层分析（直方图/幅值对比），若 NAT 模型 clean 激活幅值显著小于 clean 基线，则 H3 成立。此检验同时为 ext2/ext3 机制章节供弹药。

## 6. 对后续任务的启示

1. **vgg11 / resnet18 的 task2 结果重点看一件事**：方向再分配（Δ 随 α 单调递减）是否复现，以及再分配幅度是否与各模型的 task1 脆弱度排序相关——这将决定"对称随机 α 的 NAT 存在系统性方向偏置"是否为跨架构规律。
2. **task3 的直接动机升级**：对称均匀 α 采样已被证明无法覆盖压缩短板——**非对称/偏斜 α 采样（如侧重 +α）应作为 task3 的正式变体**，而非可选补充。
3. 建议的低成本补充实验（不阻塞主线）：① 3 seeds 重跑 scratch 确认 scratch-vs-finetune 差异方向；② NAT checkpoint 的层偏移分析（检验 H3）。
4. 写作提示：本组结果是"干净精度无损 + 方向性鲁棒再分配 + 短板加剧"的三合一叙事，比单纯"NAT 提升了鲁棒性"的常规故事更有分析价值；负结果如实报告。
