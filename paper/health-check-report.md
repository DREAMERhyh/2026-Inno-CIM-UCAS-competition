## 2. 形式层

### 2.1 ⚠ `\cref` 的两类失效场景（**均已修**，并已改成制度）

**(a) 表格单元内**：`competition` §1.3 的阶段对照表（6 处）、
`technical-report` 的阅读指南表（6 处）与复现手册的列表项（1 处）。
**处置**：表格单元内改用 `\ref{...}` 并手工补"第 … 节"。

**(b) `\cref` 指向 section 时**：`journal` §2.1 与 §3.3 各 1 处。
**现象**：`! Extra \endcsname.`，指向含 `\cref` 的整行；PDF 仍能生成，但交叉引用不可靠。
**排查结论**：给 `cleveref` 设中文名时，`figure` / `table` / `equation` **都正常**
（正文正确渲染为"图 1""表 2"），**只有 `section` 会触发该错误**。
**处置**：三份稿件**都不再给 section 设中文 crefname**，并在 preamble 里留了注释说明原因；
章节引用一律写成「第 `\ref{sec:xxx}` 节」。

**证据**：修复前 `grep -c "^!" main.log` 为 competition 6 / journal 2 / technical-report 7；
修复后**三份均为 0**。

### 2.1b ⚠ 一次自己造成的破坏（如实披露）

**过程**：修复上述问题时，我用 Python 脚本（heredoc）批量改写 `.tex`。
**结果**：脚本里的反斜杠转义在传递过程中被折叠，`\t` 与 `\b` 被解释成
**制表符与退格符**，把 `journal/main.tex` 的标题行写坏成
`\title{` + 退格 + `fseries …`（`\bfseries` 的首字母被吃掉）。
**发现方式**：编译后 `cat -A` 核对控制字符。
**处置**：改用不含反斜杠字面量的方式（`chr(92)` 构造）逐行修复；
三份稿件的 preamble 与标题现已 `grep` 复核无误。
**教训（已写进本报告的教训）**：**批量改写 LaTeX 源文件不要用字符串替换脚本，
直接用编辑工具逐处改**——转义层数一多就不可控。
