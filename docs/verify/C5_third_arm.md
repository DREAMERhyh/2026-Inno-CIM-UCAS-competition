### 1.2 为什么 `e_readout_NAT` 不能直接当第三臂（这是判定的关键）

复核者说 `e_readout_NAT` 是"功能等价的臂"——**功能上对，口径上不成立**。它与我必须匹配的探针协议有四处差异，
其中任何一处都不是可忽略的细节：

| 项 | 探针协议（M0c 规范口径，第三臂必须同口径） | `e_readout_NAT` | 为什么不能混 |
|---|---|---|---|
| 拟合过程 | sklearn `StandardScaler` + `LogisticRegression(max_iter=1000, n_jobs=None)`，**一次拟合** | torch `nn.Linear` + Adam(lr=0.01, wd=1e-4)，**24 个 epoch** | 论文自订 **Δ_proc = 3.45 pp** 就是"同数据、同特征、只换拟合过程"的极差 —— 换实现本身能移动 3.45 pp，**正好等于 C1 的判据阈值**，混用会让判据失去分辨力 |
| 训练样本数 | **8 000** | **20 000**（文件名 `n20000`） | 样本量在本项目已被测成一阶变量：oracle 臂 8k→48.35、50k→55.72（**+7.37**） |
| 评估路径 | 在特征上算 sklearn 精度 | 整模型前向 + torch 头 | `论文v3.md` 记两条路径最多差 **1.2 pp** |
| α 采样粒度 | 待定（本第三臂定为**逐样本** i.i.d.） | **每 batch 一个 α**，全层共享——原文：`alpha = 0.0 if rng.random() < clean_ratio else rng.uniform(-alpha_max, alpha_max)`（`v3_readout_repair.py`，`train_readout_nat` 内） | 粒度是已知的小效应，但仍需在报告里对齐 |

来源：`v7_probe_audit.py:54`（`PROBE_KW`）/ `:56-57`（N_TRAIN/N_TEST）/ `:171-186`（探针拟合）；
`v3_readout_repair.py:155-195`（`train_readout_nat`，α 抽样在 `:172`）；
`outputs_cifar100/v3_readout_repair/*ep24*.csv` 的 `e_readout_NAT` 行（+0.3 处 43.38 单 seed / 43.31 三 seed 均值）。
