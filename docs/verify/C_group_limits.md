## C1：读出杠杆从未在 |α| > 0.3 上评估

**缺的是什么（具体到产物范围）**

**全部读出适配产物的 α 网格只到 ±0.3。** 出处——表头逐字：

```
源文件：outputs_cifar100/v3_readout_repair/*.csv   （C100 侧 7 份）
        outputs/v3_readout_repair/*.csv             （C10 侧 7 份）
表头  ：readout,-0.3,-0.2,-0.1,0.0,0.1,0.2,0.3      ← 只有 7 个点
```

**没有任何一份读出产物覆盖 α = ±0.4 或 ±0.5。**

**因此悬着的问题是**

> **自带头在 α=+0.4/+0.5 已掉到 12.32 / 6.09，而探针 headroom 在那两处反而最大（+30.90 / +30.82）——
> 读出杠杆在那两处还能捞回多少？**

出处：`outputs_cifar100/v7_probe_audit/ra_onprotocol_main.csv`（headroom 列）；台账 §16.0 规范口径表。

**建议写法（可直接放进 §5 局限）**

> 本文的读出适配评估覆盖 α ∈ [−0.3, +0.3]。在更远的尾部（α=+0.4/+0.5），
> 冻结自带头已降至 12.32/6.09，而线性探针仍读出 43.22/36.91，**headroom 反而升至 +30.90/+30.82**。
> 该区间是否仍能被读出适配兑现，**本文未测**；考虑到读出侧同时存在固定的分类损失下限
> （见 §16.5 的样本量曲线），该处的可恢复比例可能下降。

**相关台账节号 / 产物路径**：台账 §16.0、§16.5；`outputs_cifar100/v3_readout_repair/`、`outputs/v3_readout_repair/`、`outputs_cifar100/v7_probe_audit/`

## C2：架构杠杆只在有池化的主干上验证过

**缺的是什么**

**架构杠杆（MaxPool 数量 2→5）只在 SimpleCNN 家族上做过。** 而本项目用的 ResNet-18 **架构里根本没有 MaxPool**：

```
源文件：models/resnet.py
:8    「2. 去掉初始 MaxPool2d 层：ImageNet 版 conv1 后跟一层 MaxPool(3×3,stride=2)，」
:112  「→ 【关键适配2：去掉 ImageNet 版的 MaxPool(3×3,s=2)】」
      ⇒ 全文件无 nn.MaxPool2d，只剩 AdaptiveAvgPool2d
```

**独立佐证**（同一份产物里的 `maxpool_count` 列）：

```
源文件：outputs_cifar100/extension5_dithering_vgg11/arch_dithering_summary.csv
  simple_cnn   maxpool_count = 2
  vgg11        maxpool_count = 5
  resnet18     maxpool_count = 0    ← 无法施加"池化密度"这个杠杆
```

**因此悬着的问题是**

> **对无池化的架构（现代主干的主流形态），"架构端先上"这条建议能不能落地？**

**建议写法**

> 「池化密度是独立架构杠杆」这一结论**在本文的三个主干上成立，但三者都含池化层**
> （SimpleCNN 2 个、VGG-11 5 个；ResNet-18 已按 CIFAR 适配去掉初始 MaxPool，其 `maxpool_count = 0`）。
> 对**本身不含池化**的架构（含注意力主干），该杠杆**无对应旋钮**，本文无法给出替代方案。

**相关台账节号 / 产物路径**：台账 §12.9、§13.1–§13.4；`models/resnet.py`、`outputs_cifar100/extension5_dithering_vgg11/arch_dithering_summary.csv`

## C3：CIFAR-10 侧的读出适配只有单 seed

**缺的是什么**

```
源文件：outputs/v3_readout_repair/   （共 7 份，全部无 _s43/_s44 后缀）
  readout_repair_c10_c10_mp_ep24_alpha+0.30_n20000.csv
  readout_repair_c10_c10_resnet18_ep24_alpha+0.30_n20000.csv
  …（其余 5 份同构）
```

**文件名里没有任何 seed 标记** ⇒ 每格只有一次运行。C100 侧有 3-seed（`_s42/_s43/_s44`），**C10 侧没有同口径重复**。

**因此悬着的问题是**

> **跨数据集的"恢复率标度律"（C10 83.0/86.4/34.3 % vs C100 68.6/59.8/22.6 %）是否超出 C10 单次训练的噪声？**

**一条可以补进去的量化**（本会话已有）：

- §16.4 实测**读出这一层的训练过程自由度** Δ_proc = **3.45 pp**；
- 跨数据集的恢复率差是 83.0 − 68.6 = **14.4 pp**，即 **4.2 × Δ_proc**。

⇒ **主效应远大于过程自由度**，但**单 seed 无法把"数据集差"与"这一次训练的运气"分开**。
（本节不据此下结论，只提供这个比值供写者使用。）

**建议写法**

> CIFAR-10 侧的读出适配为**单次运行**（CIFAR-100 侧为 3 seeds）。跨数据集的恢复率差
> （83.0% vs 68.6%）**远大于实测的读出层训练过程自由度（3.45 pp，见 §16.4）**，
> 但**该对比无法排除单次训练的影响**；确认需在 CIFAR-10 侧补种子。

**相关台账节号 / 产物路径**：台账 §16.4、§13.9；`outputs/v3_readout_repair/`、`outputs_cifar100/v3_readout_repair/`


**没有任何"读出适配 × 低位量化"的组合产物**（`outputs_cifar100/` 下含 dither/quant 的目录只有上面一个）。

**因此悬着的问题是**

> **叠加了读出适配之后，"低位量化在池化密集架构上是补偿"是否仍成立？**

本节的跨架构证据（同一份产物）：`arch_dithering_summary.csv` 的 `gain_4bit_vs_8bit` 列
= simple_cnn(2 pool) **−14.71** / vgg11(5 pool) **+2.84** / resnet18(0 pool) **−0.21**
⇒ 低位量化的增益**随池化密度单调变化**；但**它是在未叠加读出适配的原始头上测的**。

**建议写法**

> 本文关于「低位量化在池化密集架构上反转为增益」的证据，取自**未施加读出适配**的原始分类头，
> 且固定在 α=+0.3。**两条杠杆（低位量化、读出适配）从未在同一份产物上组合测量**，
> 二者的收益是否可加、还是互相挤占同一个机制（失真的补偿），本文无法判定。
