**为什么台账要单写者**：多个会话同时编辑同一个 markdown 会互相覆盖，而台账是本项目最权威的一手记录，
一旦损坏，前六个阶段的全部预登记判据都失去依托。

**台账的汇总流程**：工人**不直接写台账**时，把结果写进自己的 `REPORT.md`，
由 claude-e9 在工人停机后**串行**并入 §16，并在 commit message 里注明来源会话。

## 三、并行度的真正上限（不是会话数）

1. **GPU 串行**——项目出过三次事故（一次 CUDA OOM、两次 Windows 提交内存耗尽 error 1455）。
   **同一时刻只能有一个训练在跑。** M4 在跑期间，其他会话不得碰 GPU。
2. **台账写入串行**——见上。
3. **产物零覆盖**——新产物一律带 `_v7` / `_s43` / `_s44` / `_smoke` 后缀；跑前核验目标目录不存在。

⇒ 实际可并行的形态是「**一个跑 GPU 的 + 若干做零 GPU 的**」，不是"同时开五个都去训练"。

## 四、通信协议

### 派活简报必带六件套
1. 任务编号（对应 `docs/NEXT_STAGE_TASKS.md` 的里程碑）
2. 先读清单
3. **预登记判据 + 分支判决**（跑前写死）
4. 产物路径
5. 红线
6. 文件领地

**判据不写清的，不派。**

### 工人回报格式（固定四段）
```
里程碑：
关键数字 + 每个数字的出处文件：
判据命中哪个分支：
有没有触发红线：
```

### 顾问（claude-e9）的校验动作
不采信"它说它对"。每批新数字进来必做：
| 校验项 | 工具 |
|---|---|
| 台账重扫是否自洽 | `build_ledger.py` → 行数 + `pairing FAIL` |
| 派生量算得对不对 | `tools/recalc_mean7.py` |
| 数字有没有出处 | 反向检索（抽数值 token 去源材料找） |
| **有没有混协议** | `docs/IMPL_AUDIT.md` 的方法：产物路径 → 归属实现 → 查跨实现并列 |

## 五、已知的坑（实测所得，别再踩）

| 坑 | 事实 | 应对 |
|---|---|---|
| **`claude --resume` 用短 id 会卡死** | background 会话有两个 ID：`id`（给 `logs`/`stop`）与 `sessionId`（短 id + UUID） | `--resume` **必须用完整 sessionId**，且前提是会话已停止 |
| **`--bg` 会话是单向的** | 我开得出、读得到日志、停得掉，但 `SendMessage` 到不了它 | 简报必须**一次写死**；靠 `--bg --resume <完整sessionId>` 续接追问 |
| **两个版本不一致** | PATH 上的 `claude` 是 npm 版 v2.1.246；VS Code 扩展自带的是 v2.1.280 | 同一批任务固定用一份，不跨版本 |
| **跨会话来消息需要用户批准** | 当两个会话权限模式不同时，接收端会 hold 消息等用户点 | 这是设计如此，不是故障 |
| **`\` 在 Python heredoc 里会被吞** | 用 heredoc 批量改写 `.tex`/正则时，`\t` `\b` 会被解释成控制字符（本项目实际踩过一次，写坏了标题行） | **不要用字符串替换脚本批量改 LaTeX 源文件**；要改就用编辑工具逐处改 |
