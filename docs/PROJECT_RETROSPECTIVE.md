## §1 第一阶段：敏感性、NAT、架构增强、三项拓展

### ① 立项时的问题与当时的预期

赛题「存算一体芯片中非线性误差对推理精度的影响研究」。失真建模为逐样本 ∞-范数归一化之后的三次多项式 $y=\alpha\hat x^3+(1-\alpha)\hat x$，通过 `register_forward_pre_hook` 挂在每个 `nn.Conv2d`/`nn.Linear` 的输入侧（`utils/nonlinearity.py`）。

三个任务 + 三项拓展，设计逻辑是递进的（`原始题目+题目解读+研究思路+研究发现.md` §2.2）：**任务1 搞清破坏力 → 任务2 让模型"见过"失真 → 任务3 在架构层加东西**；拓展则横向扩到跨架构、跨扰动类型、多误差源。

当时的预期很朴素：先找到"最脆弱的环节"，然后针对它加固。

### ② 那时相信了什么

引当时报告原话（`原始题目+题目解读+研究思路+研究发现.md`）：

- §2.3：「正向失真破坏力是负向的 **3.4 倍**」
- §3.1：「误差从浅层向深层累积，**fc 层是最脆弱的瓶颈**（余弦相似度仅 0.895）」
- §3.2：「**Scratch 全面占优**」（SimpleCNN α=+0.3 **+9.15%**、VGG-11 α=−0.3 **+12.89%**）；ResNet-18 极限失真「**不可救（17→16%）**」
- §3.3：「**最优方案 = Exp2**：干净精度 87.37%，α=+0.3 精度 **68.76%**」（累计提升 13.68 个百分点）
- §3.3：「非对称采样（方案C）边际贡献极小（**+0.38%**），**可舍弃**」
- §4.1：「**NAT 效果与注入点数量负相关**：5 注入点 → 9 → 18，极限失真下的提升依次递减」
- §4.3：Dithering 解释为「**随机共振 / 抖动去相关**」，工程建议「在 ADC 前主动注入已知强度随机噪声」

### ③ 什么把它推翻/修正了

| 当时的说法 | 被什么推翻 | 关键数字与出处 |
|---|---|---|
| fc 层是最脆弱的**瓶颈** | 层组合探针：单层注入最敏感的是 conv2/conv3，fc 单点几乎无害 | conv2 **−12.43**、conv3 **−7.56**、fc **−0.68**；修正为「fc 是误差的**汇聚与观测**瓶颈，而非**注入**敏感点」（`第三阶段报告.md` §2.2；台账 §2） |
| Dithering = 随机共振，建议注噪 | ext5 三假设竞争判决：**H1 否决** | 等剂量注噪 **−0.03 pp**（8bit+最优剂量高斯）；H2 确认（分类器输入峰度 **0.110 → 0.214** 对应 +6.53）（台账 §4；`二阶段优化+实施记录+结果分析.md` §2.6） |
| 非对称采样「可舍弃」 | 深层上兑现了设计意图 | Exp3 在 resnet18 上 α=+0.2 = **25.56 > 23.79** 判据 ✅；第四阶段解耦确认 **+8.89 pp** 是真实效应（台账 §9.7、§12.12） |
| 「3.4 倍」不对称 | 它不是常数 | CIFAR-10/SimpleCNN/|α|=0.3 是 **3.4**；CIFAR-100 同模型只有 **1.87**（论文 §6 第 13 条） |
| NAT 是有效防御手段 | 只在训练分布内有效 | ext4：SimpleCNN nat_scratch 外推 +0.4 **+0.77**（归零）→ +0.5 **−10.77**（反转为劣）（台账 §1；二阶段 §1.6 F2） |
| Exp2「最优」 | 在 CIFAR-100 上被 1/30 成本的方法超过 | readout-NAT 8ep 即达 **44.09**（vs Exp2 在同一目标上的 ~29.89）（`第三阶段报告.md` §2.1） |

### ④ 活到收官的结论（带证据分级）

- **L1 反相关律**：clean↑ → drop@0.3↑，**同数据集内**跨容量单调（CIFAR-100：59.99/31.90 → 67.09/50.17 → 72.09/69.39）。**已确立**；跨数据集不可直接比较 drop 绝对值。
- **L5 Dithering**：4bit 增益 = 离散化分布重塑 × MaxPool 密度，**与随机性无关**（H1 否决）。**已确立**；但标度律只有两个数据点（CIFAR-10 +6.53 → CIFAR-100 **+2.84**，保留 43%），**两点连线**，第三档未验。
- **正负不对称**：跨阶段、跨架构稳定成立的只有**方向**（正侧更难防御）；**倍数不是常数**，引用时必须带条件。
- 一阶段论文里的「随机共振 + ADC 前注噪建议」**已被否证，不可再引用**。

## §2 第二阶段：外推边界、Dithering 机理、深层迁移

### ① 立项时的问题与当时的预期

对照评审意见的四条子建议（`二阶段优化+实施记录+结果分析.md` §0.1）：R1 扩 α 扫描范围、R2 Dithering 定量机理解析、R3 增强方案迁移深层网络、R4 数据集多样性（**暂缓**，已论证）。

核心问题是一个：**NAT 的鲁棒性是真泛化，还是训练分布内的过拟合？** 预期是"扩到 ±0.6 看看还灵不灵"。

### ② 那时相信了什么

- 「NAT 鲁棒性有效」——这是整个一阶段的方法基础。
- 「ResNet-18 上 Finetune 反常占优（**19.89% vs Scratch 15.64%**）」，一阶段据此给出的策略规律是「残差网络极限失真下应改用 Finetune」。
- 「分布式逐层校准」被列为一阶段的**未来工作**（尚未验证）。

### ③ 什么把它推翻/修正了

- **NAT 是分布内属性**（台账 §1，二阶段 §1.6 F2）：
  SimpleCNN nat_scratch 相对 clean 的增益随外推距离 **单调衰减**：+0.35 **+5.89** → +0.40 **+0.77**（归零）→ +0.50 **−10.77** → +0.60 **−10.89**。
  原话：「**NAT 的鲁棒性相对于训练分布有效，超出边界后不仅失效、甚至有害**」。
- **负向不对称性再证**（F3）：负侧增益随距离**不降反升**（+5.48@−0.3 → **+8.22@−0.6**），VGG-11 全区间 +5~14 pp。
- **容差窗口随深度收窄**（F5）：clean 模型保持 ≥70% 的 α 窗口 —— SimpleCNN 约 [−0.35,+0.25] > VGG-11 约 [−0.25,+0.2] > **ResNet-18 约 [−0.15,+0.15]**。
- **Exp2 可迁移，且零干净精度牺牲**（台账 §9.7、二阶段 §3.5）：VGG-11 对三条基线 **15 胜 0 平 0 负**（vs clean 平均 **+10.22 pp**）；两架构 exp2 的 α=0 精度（**91.27 / 93.27**）均为四组权重中最高。
- **但增益随深度衰减**：+13.68（SimpleCNN）→ +13.55（VGG-11）→ **+3.04**（ResNet-18）。机制（发现 3）：逐层独立采样下所有层同时取到极端 α 的概率趋近于零，而评估时全局 α=+0.3 意味着全部 17 个卷积层**同时**处于边界失真 —— 「**复合最坏情形概率的指数放大**」。
- **校准注入密度法则**（§4.3）：单点校准（仅 GAP 后）负侧外推输给 nat_scratch 最多 **−12.58 pp**；深层 5/8 个空间注入点后 **15 个扫描点全胜** → 密度应随误差累积节点数同步扩展。

### ④ 活到收官的结论（带证据分级）

- **L2 的雏形**：NAT 只在"中脆弱带"购买不变性；ResNet-18 正侧尾部在训练端不可救。**已确立**。
- **校准注入密度法则**：**提示性**（单 seed、单架构对，没有多 seed 复核）。
- **L5 机理版**：Dithering = H2（分布重塑）× H3（MaxPool 载体），H1 否决。**已确立**——但注意 H3 只是**必要条件**：无 MaxPool 的 ResNet-18 免疫（+0.39），而只有 2 个 MaxPool 的 SimpleCNN 是**负增益 −13.68**。
- **本阶段留下的一条工作习惯，此后一直在用**：「数据有效性验证前置 —— 每项实验的数据先与既有锚点逐点比对，**偏差 0.00 pp 方可采信**」（二阶段 §0.3 方法论保障 2）。

## §3 第三阶段：台账统一 + 四条新结论（含 readout-NAT）

### ① 立项时的问题与当时的预期

自主研究阶段。计划写的是"**统一与收割**"：建一个全局台账（`results_master.csv`）+ 收割 4 块此前未分析的数据（ext2 三架构 / ext3 加性 / ext5 三假设 / 零迁移复判），再用**低成本高诊断**的实验改写既有结论。

当时的预期是"收尾整理"——按计划，这一阶段的产出主要是**核对**。

### ② 那时相信了什么

- L1/L2/L3 三条定律（第二阶段的终版）。
- 一个隐含前提：**所有补救手段都在训练端**。前两阶段的预算分配、对抗、课程式、架构增强，无一例外是在改训练。
- 「fc 层是最脆弱瓶颈」——用它来给方向排序。

### ③ 什么把它推翻/修正了

**这一阶段的产出几乎全是"推翻"。**

- **建立台账**：`results_master.csv` **48 行，配对自检 0 FAIL**（`第三阶段报告.md` §1.1）。
- **★ 信息未死**（台账 §6，`第三阶段报告.md` §2.1 证据链 1）：
  α=+0.3 时，同条件线性探针在**冻结主干的 fc 输入特征**上达 **47.89%**，而冻结头只有 **27.76%** → **headroom +20.12 pp**（α 越强 headroom 越大：+0.4 时 +30.41、+0.5 时 +30.38）。
  → **灾难尾不是信息死亡，而是"读出无法解码仍在表征中的标签信息"。** 这一条直接改写了问题定义。
- **★ readout-NAT**（台账 §9）：冻结全部主干权重、只重训最后的线性读出（8ep，4~15 min），三架构 α=+0.3：

  | 架构 | 原始 fc | readout-NAT | Δ |
  |---|---|---|---|
  | SimpleCNN | 28.09 | **41.16** | +13.07 |
  | VGG-11 | 16.92 | **40.14** | +23.22 |
  | ResNet-18 | 2.70 | **16.27** | +13.57 |

  **成本 1/15 ~ 1/30，全面超过所有全网络配方**（含 task3 Exp3 与 ext6 Exp2）。工程含义：「不改动芯片上的模拟权重，只改数字域读出」。
- **训练端四条路全负**（→ L4 的四条独立证据）：
  ① 预算分配（4 轮廓，最好 26.13 ≤ 基准）② α-对抗（24.32，−1.71）③ 课程式（21.78，−4.25）④ **训练范围外推 ±0.5**（20.48，−5.55）。
  最强的一条是 ④：**即便模型在 ±0.5 上训练过**，测试 α=+0.5 仍只有 **2.71%**，同期负侧 −0.5 有 **31.19%**（差 **28.5 pp**）→ **正侧尾部不是采样覆盖问题，是结构性的不可训练区**（台账 §9.5/§9.6/§9.9）。
- **L3 需修订**：VGG-11 的高斯迁移非零（max Δ = **+5.26 pp**）→ 零迁移是**架构依赖的**（SimpleCNN 1.16 / ResNet-18 1.41 成立，VGG-11 被打破）。
- **旗标②被推翻**（台账 §8）：校准模块不是欠拟合元凶。无校准的 NAT 训练精度反而**更低**（72.41 / 74.22 vs 含校准的 75.60 / 76.04）→ 真因是**容量**（0.25M 参数的 SimpleCNN 在"100 类 + 逐层失真"下拟合不了训练集；VGG-11 训练精度达 99.97%）。

### ④ 活到收官的结论（带证据分级）

- **L6 读出瓶颈律**（本阶段新立）：α 失真的信息损伤主要**不发生在表征、而发生在读出**。**已确立**（四架构 × 双数据集）。
- **L4 的完整版**（本阶段成型，第四阶段命名）：正侧尾部是结构性不可训练区，**四条独立负结果**。**已确立**。
- **L2 补上可达性边界**：中带（|α|≤0.2）全架构可救；正侧尾在**训练端**不可救、在**读出适配**下可**部分**救。
- **必须披露的事故**：并发 4 个带 DataLoader worker 的任务 → Windows 提交内存耗尽（**error 1455**），中断 Exp3 训练与两个探针 → 此后改为**严格串行**，成为全项目红线（`第三阶段报告.md` §7）。
- 另一处已修的 harness bug：读出脚本早期版本用 `model.fc(f)` 会**二次触发** fc 上的失真钩子（双重失真），使 α=−0.3 处偏低 **2.34 pp**；修正为 `F.linear(f, w, b)` 并重跑后与台账逐位一致。

## §4 第四阶段：读出端 vs 训练端

### ① 立项时的问题与当时的预期

围绕第三阶段最重要的那条分界线——**读出端 vs 训练端**——做分解。四个具体问题：NAT 训练是否在特征层赔掉了可解码性？读出适配能不能叠加到已训好的深层鲁棒主干上？跨数据集是否复现？失真强度能不能在线估？

### ② 那时相信了什么

- readout-NAT 有效（第三阶段头条）。
- **「clean 代价是该方法的固有属性」**——第三阶段的 `clean_ratio` 缓解实验判为"权衡中性"，报告里明确写了"应作为固有属性接受"。
- MaxPool 只在 L5/Dithering 的语境里出现过（是 Dithering 的**载体**，不是独立杠杆）。

### ③ 什么把它推翻/修正了

- **NAT 主干没有赔掉解码性**（台账 §12.1、§12.4）：探针在 clean 主干 47.89 vs NAT 主干 **47.69**（差 0.20 pp）；此前观察到的 5.26 pp 差距**主要是读出欠训练** —— 读出从 8ep 延到 24ep 后差距缩到 **1.78 pp**。
  → **方法论副产品**：「本阶段之前所有 readout-NAT 结果（8ep）均为**下界**」。
- **「clean 代价是固有属性」被推翻**（台账 §12.6）：在线 α 估计（岭回归）+ 阈值路由达 **52.82**，距 oracle 仅 **0.20 pp**，比 always-robust 高 1.80 pp，且 α=0 处 **59.97**（只比原始头低 **0.02**）→ **代价可消除**。
- **「MaxPool 密度诱导高斯迁移」否证**（台账 §12.7）：给 SimpleCNN 加 3 个 MaxPool，迁移反而从 **2.43 降到 0.98**。
- **★ 意外发现（正面）**（台账 §12.9/§12.10）：**MaxPool 密度本身是独立的架构级杠杆**——单纯把 MaxPool 从 2 个加到 5 个（**零训练成本**、纯架构改动）：

  | 训练协议 | 原架构 +0.3 | 5×MaxPool +0.3 |
  |---|---|---|
  | clean 训练 | 28.09 | **42.47**（+14.38） |
  | NAT-scratch | 21.41 | **41.55**（+20.14） |

  且**与读出杠杆正交可叠加**（`5×MaxPool + readout-NAT` 的 +0.3 达 **49.12**）。
- **P1-4 推翻"＋α 无界放大"的直觉**：+α 是**压缩器**（衰减中段），−α 是**放大器**，且随深度累积（fc/conv1 的 L2 比 0.45 → **0.23** / **0.71**）（台账 §12.2）。

### ④ 活到收官的结论（带证据分级）

- **L7 可路由律**（新立）：失真是可在线估计的（岭回归，MAE 小）；"按估计 α 路由双头"可达 **oracle − 0.20 pp**，且消除单头方案的 clean 代价。工程含义：不必在"鲁棒头"与"干净头"之间取舍。
- **两个正交杠杆**：架构端（MaxPool 密度，零成本）+ 读出端（冻结主干只训头，≈12 min）。
- **部署表 v1**：主干选择与架构相关（VGG-11 偏好 Exp2、ResNet-18 尾部偏好 Exp3、均值偏好 Exp2）。
- **⚠ 本阶段立的那条方法学规则，当轮就被自己写歪了**：§12.11 把 NAT-scratch 的 3 seed 尾部记作"**种子噪声 ±3.15 pp**"，并据此立下"单 seed 的尾部差值 <3 pp 不构成结论"。**那条规则本身是对的，但它引用的数字是混协议读数**——见 §5 与 §7.1。

## §5 第五阶段：完整配方、池化成因、CIFAR-10 复制

### ① 立项时的问题与当时的预期

把第四阶段的两条主结论（读出瓶颈、MaxPool 杠杆）推进到"**机制 + 端到端配方**"。终审裁决另指定了一项：**L8 保护分解的 3-seed 精简复核**（5×max / 5×avg 各补 seed 43/44，共 4 次训练）。

### ② 那时相信了什么

- 第四阶段推算的**「完整配方 ≈ 54.5」**（`5×MaxPool 主干 + 双头 + α 估计 + τ 路由`，组件全部单独验证过，整体待实测）。
- **「插值即集成」**：软门控（logit 插值）在 CIFAR-100 上三判据全达标（55.08 / 60.70 / 49.10），且**超过硬选择的 oracle（54.96）**——这是"看到硬路由失败后"引入的事后变体。
- L8 的「**降维 66% / 非均值聚合 34%**」2 : 1 分解（单 seed）。
- 「不变区集中假说」——保护来自质量向恒等区集中。

### ③ 什么把它推翻/修正了

- **「≈54.5」作废**：实测 mean7 = **54.49**（巧合命中）但 **+0.3 = 47.90**（推算引用的 49.12 来自**不同实现**的头）。用户的事前判断正确。
- **★「插值即集成」未复现**（台账 §13.7）：在**尚无任何配方结果**的 CIFAR-10 上、锁定全部超参、**跑前写死判据 C1–C5**——一次真正的事前预登记。结果：C1∧C2∧C3 形式成立，但
  **C4 由 3/7 降到 1/7**；软门控 − oracle 由 **+0.12 → −0.07**；门控红利（soft − robust 头）mean7 由 **+2.90 → +0.17**。
  → 降级为「**弱支配**」，机制替换为**门控红利 = 鲁棒头 clean 代价的回收量**。
- **★ L8 的 2:1 分解降级**（台账 §13.8）：3 seeds 同协议下 5×max drop **20.60 ± 1.54**、5×avg drop **21.78 ± 0.91**，**avg − max = +1.17 pp**，落在预登记的 **1~2 pp 区间（判据 ③）** → **"初步"，不予裁决**。
  差值的标准误 ≈ **1.03**（**z ≈ 1.1**），3 seeds 分辨不出这 1.17 pp；升为定论需 **≥8 seeds/组**。
  单 seed 时的 4.53 pp 已确认为**采样产物**（seed 42 的 5×max drop 恰是其 3 seed 中**最低**的一个）。
- **不变区假说否证**（台账 §13.2）：5-pool 的易感度 S **更高**（conv4：**0.1527** vs 0.1134）、不变区占比几乎不变；唯一显著差异是**空间元素数 16 vs 256**。
- **交换律**（台账 §13.1）：在失真实际作用的域（**非负激活**）上精确可交换，**max|Δ| = 0.000e+00**；破缺只出现在含负值张量上，原因是 `abs-max 归一化 vs signed-max 池化` 的实现不一致——**工程注记，不是成因**。
- **⚠ clean 方差不可外推**（台账 §13.6b）：ResNet-18 第 3 个 seed 的 clean = **67.61**，比另两 seed（63.54 / 63.84）高 2.6~4.1 pp → **2-seed 时报的 "±0.15" 是采样假象**，3-seed 下是 **±1.85**（浅层只有 ±0.07~0.12，**跨度 26 倍**）。

### ④ 活到收官的结论（带证据分级）

- **L8 池化保护律**：保护**主要来自降维**。三条排除线是**稳健**的（不来自"吸收失真"——可交换却非成因；不来自"不变区集中"；不来自"max 的选择性/可交换性"——**top-2 不可交换却与 max 等同**：42.98 vs 42.47，单 seed）。非均值聚合成分 **"初步"**。
- **L7 修正版**：门控红利 = 鲁棒头 clean 代价的回收量（CIFAR-100/mp **−5.89 → +2.90**；CIFAR-10/mp **−0.87 → +0.17**；CIFAR-10/plain **−0.54 → −0.28**）⇒ **代价 ≲1 pp 时直接用单鲁棒头**。
- **软门控维持「事后变体 + CIFAR-100 特化」，不升格**（方法论旗标 ⑨）。要断言它严格优于单鲁棒头，需在 CIFAR-10 上补 2 个**主干** seed——**这条后来在第六阶段 P2-7 做了，见 §6**。
- **Dithering 标度律**在这一阶段被复述，但仍是**两点**。

## §6 第六阶段：定律化与落地

### ① 立项时的问题与当时的预期

主题：**定律化与落地**。把前五阶段的经验配方升级为有预测力的定律，并补落地推演。

四个方向：P0 采样粒度假说验证 → P1 秩塌陷 ↔ 读出可恢复的定量曲线 → P2 深层主干的门控行为 → P3 硬件语义对齐（0 GPU，纯文档）。

**预期**（写进预登记）：P0 大概率"提示性成立"并升级为一条新定律；P1 能画出曲线；P2 能给门控划出适用边界。

### ② 那时相信了什么

引台账原话：

- §13.12：「**目前唯一可辨识的实现差异就是 α 采样粒度**」（两脚本的优化器、batch、epoch、调度器、增强、归一化、模型定义、seed 已**逐项排除一致**）。
- §13.12：「4.62 是**纯协议尾部标准差（±0.392）的约 11.8 倍** → 几乎不可能是种子噪声」。
- §14.5：差异定为「**根因是 RNG 流错开**」（v3-shared 消耗 5 个随机数、task2 只消耗 1 个，第 1 个 batch 相同、之后完全错开）。
- L4（秩塌陷）与 L6（读出可恢复）是**两条分开的律**，中间没有定量连接。
- L7 的「**门控红利 = 鲁棒头 clean 代价的回收量**」（六点 $r=-0.994$）。

### ③ 什么把它推翻/修正了

**这一阶段是本项目"自己推翻自己"最密集的一段。**

**（一）三次归因，三次失败**

| 轮次 | 当时的定性 | 被什么否证 | 关键数字 |
|---|---|---|---|
| §13.12 / P0 | 「**粒度**效应 5.54」 | P4a **同脚本**消融（只改粒度） | shared **26.55** vs per-layer **26.57**，差 **+0.02（z=0.08）**；而同粒度跨脚本差 **5.52（z=9.4）** |
| §14.5 / P4e | 「**RNG 消耗位置**」 | P4f 干预（消耗数 5→1） | consume-1 **26.66** vs consume-5 **26.55**，差 **+0.11** |
| §12.11（第五阶段） | 「**种子噪声** ±3.1」 | §13.10（同脚本补跑） | 同协议 ±0.392 vs 混协议 **±2.561**（估高约 **6 倍**） |

→ 「**效应跟着脚本走，不跟着粒度走**」；`task2_nat.py` 的 ~21 定性为
**"实现特定读数（归因未竟）"**，**按 known-unknown 收官**。
**已排除**：种子噪声、采样粒度、RNG 消耗数、评估路径（交叉评估 **8/8 逐位相同**）、训练动力学（逐 epoch loss 差 **≤0.016**）。

**（二）L7 的两前提版**

P2 加了第六、七个点（深层主干）。**代价确实落进 2~5 pp 空档**（VGG-11 −3.45、ResNet-18 −4.36），
**但红利没跟着涨**：+0.68 与 **−1.14**（ResNet-18 上门控**比单用鲁棒头还差**）。
七点 $r=-0.533$；**去掉 CIFAR-100 远点后 n=6，$r$ 反转为 +0.351**。

ResNet-18 的逐 α 曲线把原因钉死了：**它的自带头在负侧是崩的**（α=−0.2 只有 **10.27**），
软门控按 $w=|\hat\alpha|/0.3$ 插值，在 α=−0.2 处 $w\approx0.67$ → 三分之一权重的坏头把 45.64 拖到 39.21。
→ L7 改写为**两个前提**：① 鲁棒头 clean 代价够大；② **两个头在整个 α 轴上都不能崩**。

**（三）"两头不崩"的自检做不成**

P4d 第一件（零 GPU）：把"崩"写成量化判据，在已有的 7 个 $m$ 点上验证能否分离 $m$ 的符号。**判决：否定。**
两种定义都分不开 —— A（min 两头）在 $m>0.05$ 组是 [15.73, 71.83]、$m\le0.05$ 组是 [2.77, 69.23]，**重叠**；
VGG-11 的 A 只有 **15.73**（最低）却 $m=+0.68$；C10/mp 主干 43 的 A 有 **69.23**（最高之一）却 $m=-0.003$。
→ 降为**对 ResNet-18 那一个案例的事后机制解释**，不是可用的预测规则。剩下的仍是两条**各自独立**的理由（代价太小 / 有一头崩了），**没有一个统一判据能同时抓住**。

**（四）C1 改判**

P2-7 把 CIFAR-10 的 mp 主干补到 3 个 seed：$m$ = **+0.169 / −0.003 / +0.171** → **任一 $m\le0$ → 判据②命中**：
**C1 改判「不可分辨」，软门控在 CIFAR-10 上的定性定为"与单头不可区分"。**
（两个 +0.17、一个 −0.003，平均值 +0.112，全部远小于主干级 mean7 噪声。部署推荐不变——只变措辞。）

**（五）"红利=代价回收"的线性度检验没通过**

七点 $r=-0.994$ 被拆开：CIFAR-10 的四个点挤在 **−0.54 ~ −1.04** 的 0.5 个点窄带里，
红利只在 −0.28 ~ +0.17（跨度 0.45）之间摆动。**去掉 CIFAR-100 那个远点后 n=4，$r=-0.675$，看不出单调性。**
**正向检验点没有通过**：主干 seed 43 的代价是 **−1.04**（刚过 1 pp），红利是 **−0.00** —— 代价变大了，红利没有跟着变大。**阴性结果，照实记。**

**（六）P3 落地推演（唯一没有"推翻"的一节，因为它是纯文档）**

`deploy_notes.md` 的三档判定：
**需改动** = readout-NAT（读出层必须在数字域或可重写，占全模型参数 **5.04%** / **0.55%**）；
**可行** = 在线 α 估计（占主干 MAC **3.8e-4%**）、软门控（约 **400** 次操作）；
**设计阶段零成本 / 部署后不可行** = MaxPool 密集主干；
**不可行** = 全网络重训。

### ④ 活到收官的结论（带证据分级）

- **L6 的推广（P1）**：秩损失 **20.6% / 33.3% / 58.7%** 对应恢复率 **72.2% / 70.2% / 36.9%**（$r=-0.960$）→ **「趋势成立，三点不足以定曲线形状」**。形状提示「**先平后塌**」进停车场。**提示性**。
- **L7 两前提版**：**已确立**（两个深层点 + 原有五点，七个点）。
- **训练实现的可移植性**（本阶段最重要的一条工程结论，来自三次失败的归因）：
  **任何精度数字不可跨训练实现移植；部署校准必须与部署训练同实现、同路径。**
- **粒度无影响**（同脚本差 **+0.02**）；**消耗数无影响**（差 **+0.11**）。
- **两条新制度**：
  **§13.13** —— 降级一个数字，必须扫它的**整条引用链**（含派生量）；
  **§13.14** —— 方差对比三要求（**同脚本** / **已交叉评估** / 未校准的组必须标注）+ 第四条（**跨实现比较前先做消耗数等价检查**；"同脚本 + 交叉评估"**不足以**让两套跨脚本数字可比）。

## §7 专题：三次"噪声→翻案"

三次都满足同一个形状：**一个被当成"噪声"或"实现细节"的差异，被重新命名成一个"效应"，又被实验否证，最后回到未知。**

---

### 7.1 ±3.15 混协议

**误判链条**

1. 第四阶段 §12.11 拿 NAT-scratch 的 3 个 seed：α=+0.3 = **21.41 / 26.73 / 26.95** → 记作「**尾部噪声 ±3.15 pp**」（同期 clean 只有 ±0.51）。
2. 该节据此立下全项目规则：「涉及尾部指标的对比必须 **≥3 seeds**；单 seed 的尾部差值 <3 pp 不构成结论」，并回标受影响的结论（adv 的 −1.71、预算 rear 的 −0.57、Exp3 在 resnet18/vgg11 上的 +0.90/+2.80）。
3. **但这 3 个 seed 来自 2 个脚本**：s42 来自 `task2_nat.py`，s43/s44 来自 `v3_methods_simplecnn.py --mode plain`。

**什么把它推翻**

第五阶段 P1-6（台账 §13.10）补跑同脚本的 plain s42，**顺带项**查出一件更意外的事：新跑的 `plain_uniform` 与既有的 `v3_budget_uniform` **逐位一致**（best_clean 均 60.85 @ ep112，7 点扫描 7 个数全同）——即**预登记里写的"同脚本下 plain 只有 s43/s44"是错的**，两条代码路径逐字相同，s42 一直存在，只是记在别的名字下。**这一跑实际变成了一次可复现性验证。**

| 口径 | clean std | α=+0.3 std |
|---|---|---|
| **纯协议**（三个都来自 v3_methods，n=3） | ±0.419 | **±0.392** |
| 混合协议（§12.11 原样） | ±0.412 | **±2.561**（ddof=0；±3.15 是 ddof=1） |

→ **方差被估高约 6.5 倍。** §14.4d ② 补上定量分解：混合组里 21.41 与 26.73 差 **5.32**，与实测的**脚本级处理效应 5.52** 几乎相等 —— **那个 ±2.56 里绝大部分不是随机噪声，而是两种训练配方之间的系统差。**

**制度补丁**

- **§13.14 第 1 条**：方差对比必须**同脚本、同一采样代码路径**。
- **§13.13**：降级一个数字必须**扫整条引用链** —— 因为 §13.10 降级时只改了 §12.11 本身，而它派生出去的数字还在下游活着（§3.4 曾用混协议的 25.03 算架构增益；L8 表里的那一行更隐蔽，见 7.2）。
- **§13.10 新增 ddof 口径统一**：统一用 **ddof=0（总体标准差）**，每处标出（n=3 下两种口径差约 1.22 倍，不足以上下判据分支）。

**分层结果（不许一棍子打死）**

1. 具体数值 **±3.15 降级为"混协议读数"**，历史值降为脚注保留（不删除——§12.11 那条建议本来就是基于它提出的）。
2. 规则「尾部比 clean 抖」**保留，但证据换成同协议的**：浅层 NAT **±0.39**、架构变体 ±0.95~1.58、深层读出 ±3.18~3.40、同组 clean ±0.07~1.85。**实测范围 ±0.39 ~ ±3.40，仍普遍大于 clean。**
3. 「必须 ≥3 seeds」**不变，且理由更强**：连"尾部方差有多大"本身都需要 3 个种子才测得准。

### 7.2 粒度假说

**误判链条**

1. 第五阶段 §13.12 把 §13.10 顺带查出的 **4.62 pp** 差（同 seed 42：task2 是 21.41、v3 是 26.03）登记为**候选定律**：「α 采样粒度（每批共享 vs 逐层独立）」。
2. 支撑论证很硬：「4.62 是纯协议尾部标准差（±0.392）的约 **11.8 倍** → 几乎不可能是种子噪声」；且两脚本的 8 项实现细节**已逐项排除一致**（SGD 超参、batch 128、120ep、CosineAnnealingLR、RandomCrop+Flip、Normalize、模型定义、seed 42）→ **「目前唯一可辨识的实现差异就是 α 采样粒度」**。
3. 「方向反直觉」还被当成支持证据：每 batch 共享 α 的训练分布与测试条件更匹配，结果**反而更差**。

**什么把它推翻**

第六阶段 P0 先跑出**判据分支①「提示性成立」**：同脚本复跑 seed 43/44，两个新值（22.02 / 19.67）都落在预登记的 21±2 区间内；
尾部差 **26.57 − 21.03 = +5.54**，$SE=0.618$，**$z = 9.0$**。

**但这个"提示性成立"仍然是跨脚本对比。** P4a 在**同一个脚本里只改粒度这一个变量**：

| 对比 | 差 | SE | $z$ |
|---|---|---|---|
| **同脚本、换粒度**（v3: shared vs per-layer） | **+0.02** | 0.252 | **0.08** |
| **同粒度、换脚本**（shared: task2 vs v3） | **+5.52** | 0.588 | **9.4** |

→ **判据②命中：粒度归因失败。** 「这个效应**跟着「脚本」走，不跟着「粒度」走**」。

**制度补丁**

- **§13.14 第 2 条**：涉及跨脚本比较时，**先做一次交叉评估**（把 A 的权重量到 B 的评估路径下），确认评估侧无差。
- **§13.13 的实战案例**：P0 的有界复查在扫引用链时查出了**勘误 10** —— `论文v3.md` §2 的 L8 表里，「NAT 训练」那一行的 **clean 60.70 与 +0.3 21.41 来自 `task2_nat.py`，而 mean7 49.24 来自 `v3_methods`**：**同一行内混了两个脚本**，比勘误 3 更隐蔽。已全部改为 60.85 / 26.03 / 49.24，架构增益由 +20.14 改为 **+15.52**。
- **顺带修出的一处界**：第五阶段报告 §3 部署表原写「全网络 NAT/Exp3（尾部目标）| **≤ 24.69**」——但同协议下全网络 NAT（逐层独立）的 3-seed 均值是 **26.57**，**高于 24.69**，那个「≤」不构成上界。已改为写出两个最好值（26.57 / 24.69）。「不推荐」的结论不变。

**最深的一条教训**

**"逐项排除混杂"这种论证在跨实现比较里不成立。** 两脚本的 8 项都一致、训练 loss 逐 epoch 差 ≤0.016，效应却稳定存在。
**没查出差异 ≠ 没有差异。**

### 7.3 RNG 消耗数

**误判链条**

1. §14.4a 判出"效应跟着脚本走"后，P4e 用**交叉评估**做决定性二分：`v6_p4e_crosspath.py` 把 8 个权重分别在两条原生评估路径下扫 7 点。
2. 结果 **8/8 个权重、两条路径逐位相同**（差 **0.00**），连带 clean 也逐位相同 → **判据②命中：差异在权重本身（训练侧）**；**评估路径无辜**。
3. 训练侧审计：同 seed 43 的逐 epoch 训练 loss 全程贴合（ep1 4.0076/4.0105，全程差 **≤0.016**，没有分叉）→ **排除"训练动力学不同"**。
4. 剩下的唯一可辨识差异是 α 的**具体序列**：`v3_methods` 的 `shared` 实现**有意**消耗 5 个随机数（为了让默认路径 RNG 流逐位不变），而 `task2_nat.py` 只消耗 1 个 → 第 1 个 batch 相同，**第 2 个 batch 起完全错开**。
   → §14.5 判决：「**根因是 RNG 流错开**」，并给出可跟"组内极紧"吻合的解释。

**什么把它推翻**

P4f 预登记里自己写明了：「那是**观察性**结论（两脚本还有别处不同）。**消耗数是否因果，必须同脚本干预确认**。」
干预实验：`v3_methods` 加 `--alpha-consume {1,5}`，同脚本把消耗数从 5 改成 1（其余一切不变，默认路径已冒烟验证逐位不变）：

| 配置 | 种子 | α=+0.3 | clean |
|---|---|---|---|
| **consume-1**（干预） | 42 | **26.66** | 60.26 |
| consume-5（对照） | 42 / 43 | 26.71 / 26.39（均值 **26.55 ± 0.16**） | 60.51 / 60.50 |

差 **+0.11** → 判据②命中：**RNG 消耗数不是因果；§14.5 的归因同时被否证。**
顺带记录：clean 差 **0.25**（< 预登记的 0.5 pp 阈值）→ **不记为机制线索**。

**制度补丁**

- **§13.14 第 4 条**：「同脚本 + 交叉评估」**不足以**让两套跨脚本数字可比 —— `task2_nat` 与 `v3_methods` 的 NAT 结果**永久不可混用**，直到机制查清。
- §13.14 的**代价记录**（原文）：「两套 NAT 结果的 5.5 pp 组间差，从 §12.11（记作"种子噪声 ±3.1"）一路漂到 §14.5 才查清，中间经过了三次误判（噪声 → 粒度 → 脚本未知差异）。**三层的根因都是"没做交叉评估"。**」

**最终图景**

- `task2_nat.py` 的 NAT 权重稳定落在 **21.03 ± 1.00**（3 seed）。
- `v3_methods` 的**六个** run 全在 **26.58 ± 0.29**。
- 两组之间 **5.55 pp，$z = 9.4$** —— **原因未查清**。
- **核心谜题（写进停车场第 0 条）**：**同脚本内换 seed 的流差异只值 ±1，而跨脚本的组间差稳定 5.55。**

**三次翻案的共同点**

三次都是**用自己的实验推翻自己上一轮的结论**：P0 推翻 §13.12 的候选假说 → P4a 推翻 P0 给出的"提示性成立" → P4f 推翻 P4e 给出的"根因"。三次的根因按 §13.14 原文都是**"没做交叉评估"**——或者说，**在跨实现的比较里，任何没有做干预实验的归因都只是命名，不是因果**。

### (4) 上手时最容易踩的三个坑

1. **跨脚本比数字。** `task2_nat.py` 与 `v3_methods_simplecnn.py` 训出的 NAT 权重稳定差 **5.55 pp**（21.03±1.00 vs 26.58±0.29），评估路径已验证**无辜**。⇒ **任何精度数字不可跨训练实现移植；部署校准必须与部署训练同实现、同路径。**
2. **拿单 seed 的尾部差值当结论。** 尾部 seed 方差同协议实测 **±0.39 ~ ±3.40**，深层 clean 也能到 **±1.85**。⇒ **尾部差值 <3 pp 不当结论；深层的一切指标都要 ≥3 seeds。**
3. **算方差前不确认协议纯不纯。** 混协议会把方差估高约 **6 倍**（0.39 → 2.56）。⇒ 做方差对比前，**先确认这几个 run 出自同一脚本、同一采样代码路径**。

### (5) 这个项目的行为准则（三条，都是被事故教出来的）

1. **判据跑前写死，跑后不改。** 六个阶段的每个实验都在台账里留了预登记。
2. **产物零覆盖。** 新产物一律带 `_s43` / `_tag` 之类后缀；训练脚本的每个新开关都保证**默认路径逐位不变**（冒烟验证后才跑）。
3. **降级一个数字，必须扫它的整条引用链**（含均值、差值、占比这些**派生量**——它们不带原值，grep 抓不到）。见 §13.13。
