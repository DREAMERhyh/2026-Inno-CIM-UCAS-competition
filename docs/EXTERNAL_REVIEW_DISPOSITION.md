## 8. ⚠ 一次双向失误：我错误地指控了顾问的方法（**已入坑表，完整留档**）

**我当时的判断**：顾问用「`pdftotext` 端到端字符比对」判定"①②③ 在 PDF 里一个不剩"，
但我跑 `pdftotext main.pdf - | grep -c "结论"` 得到 **0** ⇒ 认定"pdftotext 提不出中文，它的方法失效"。

**我错了。** 顾问反驳并给出可复现证据，我逐条验证后确认**它对**：

| 项 | 我 2026-09-25 的实测 |
|---|---|
| 本机有几个 `pdftotext` | **两个**：`/mingw64/bin/pdftotext`（**默认命中**）与 `/d/texlive/2025/bin/windows/pdftotext` |
| 默认那个（**无** `-enc UTF-8`） | `结论`=**0**、`α`=**0**、`①`=**0** —— **全部非 ASCII 被静默丢弃** |
| 加 `-enc UTF-8` 后 | **提取成功（非零）** ⇒ 那个 0 确是工具，不是 PDF |
| 顾问用的 TeX Live 版 | 默认 UTF-8 ⇒ 它的计数是**测量结果**，不是工具盲区 |

**⚠ 后两层坑（顾问第三、四轮查出；我第一版表述被它纠正 —— 见下）**

**同一版 PDF**（sha256 `7861ea299067c701…`，双方一致），三种计法：

| 计法 | mingw64 版 | TeX Live 版 |
|---|---|---|
| **Python `str.count`（码点次数）** | `结论`=**37** `⇒`=**26** `①`=**7** | `结论`=**37** `⇒`=**26** `①`=**7** |
| `grep -c`（**行**数） | 31 / 25 | 36 / 26 |
| `grep -o \| wc -l`（次数） | 37 / 26 | **1 / 1** |

**第三层：计法**。`grep -c` 数的是**行**（同行多个匹配只算一次）⇒ 随换行位置变（31 vs 36）；
`grep -o | wc -l` 对 TeX Live 版给 1（真值 37）。

**第四层（根因）：字节层。** 两份输出落盘后逐字节看：

| | 字节数 | 行数（CRLF） | **NUL 字节** |
|---|---|---|---|
| mingw64 | 97 906 | **1 292** | **0** |
| TeX Live | 100 228 | **2 372** | **1 019** |

⇒ **行数差近一倍**：不是"各自数各自的行"，而是**两份输出的行根本不是同一批行**。
⇒ **TeX Live 那份含 1019 个 NUL**（成串出现在 ASCII 残片里，**不在中文位置上**）⇒
**`grep` 会把它当二进制处理**，这才是计数分岔的机制。NUL 的来源未查明，按规矩记已知未知。

🔴 **我在这条上错了第二次（超范围推断）**：我写过"两个 `pdftotext` 提取的内容**逐位一致**（Python 证明）"。
**这句不成立** —— Python 只证明了**那两个字符的计数**相同，推不出"内容逐位一致"。
（顾问的纠正；我落盘复验后确认它对。）
⇒ 教训与「报"会怎样"时机制的每一环都要有支撑」是同一条：**证据支持到哪一层，话就只能说到哪一层。**

⚠ **还有一条更根本的**：同一条 `grep -o` 命令，顾问在 bash 里跑给 **7**、在 Python 里跑给 **0** ⇒
**它的行为不可稳定复现** ⇒ **连"它少报"这个判断本身都不该当作结论**。

⇒ **本项目的口径**：**数 CJK 次数一律用 Python `str.count`**，并**先做阳性对照**。
⇒ **一般化（顾问提出，我采纳）**：**一个数如果换个跑法就变，那它不是"数"，是"这一次跑出来的东西"。**
我们的第一反应都是去解释"它为什么少报"，而不是先问"**它能不能稳定复现**"。

**顾问给的对照实验更是决定性的**：修复前的 PDF 里，**唯一**被提取出来的 `⇒`（1 个）出自源码的
`$\Rightarrow$`（数学模式），而 24 个字面 `⇒` 全部丢失 —— **同一个符号、两种写法、两种结果**。
若那个 0 是工具盲区造成的，这 1 个也提不出来。

**⇒ 我的错误性质**：拿到 0 之后**没有做阳性对照**（拿一个确定存在的字符测同一个工具），
就直接下了"工具提不出中文"的结论 —— **这正是我用来批评顾问的那条纪律**
（「报工具抓到 X 之前先验工具本身」）：我引它去验顾问的方法，**却没拿它验我自己的命令行**。

**⇒ 本条完整保留、不简化成操作提示**，因为这次失误是**双向**的：
顾问**没写清用的是哪个 `pdftotext`**（照字面复现必然拿到不同结果），
我**没做阳性对照**。两人各自违反了同一条纪律的一半。

**⇒ 一般化的教训**：**报告"成品里没有 X"或"工具报 0"之前，先拿一个确定存在的东西做阳性对照。**
**对照也是 0 ⇒ 是工具问题，不是结论。**
