## 一、方法

按目录特征归属到产出它的脚本。再单独扫一遍 `task2_nat.py` 的**特征数字**（该脚本产物的独有读数），

> "（组内两个数相差 5.32，与实测的脚本级处理效应 5.52 几乎相等）"

这是**对问题的说明本身，不是作为结果引用**，且原文已给出两个数字的不同归属。

### 2.2 技术报告版（`paper/technical-report/`）—— **判据触发，已处置**

**产物路径侧**：14 条，**零条属于 `task2_nat.py`** ✓

**但正文侧**命中多个 task2 特征数字，集中在两处：

| 位置 | 数字 | 判定 |
|---|---|---|
| §3.2「第一、二阶段」的任务 2/3 表 | `64.23` `44.74` `15.64` `56.08` `39.96` `19.89` | **合法**——那一节讲的就是第一/二阶段，而那个阶段的实现**就是** `task2_nat.py` |
| §4「三次翻案」 | `21.41` `22.02` `19.67` `5.32` | **合法**——那是**混协议 bug 的历史记录**，数字本身就是证据 |

**但发现一个真实问题**：这份文档把「第一/二阶段（task2 系）」与「第三~六阶段（v3/v5 系）」的数字
放在**同一份文档**里，**却没有标注哪些来自哪个实现**——而它自己 §4 的结论正是"跨实现不可移植"。
读者会不知道哪一段是哪个实现的，从而可能做跨节的定量对比。

**处置（已执行）**：在 §3.2 开头加了一个**口径注**，写明两条实现线的归属，
并明确"**只作定性对照，不作定量对比**"。编译通过（18 页 / 0 错误 / 0 未定义引用）。
